Write-through — the deliverable owns the tick, the file follows
Both directions write. That is the ask, and it is also the first time this tool edits your markdown without you typing in it — so the guard rails are part of the design, not an afterthought.

Nearly free — this path exists today as the chip's own tick.
Direction 2 — tick on the Project tab
Token refresh endpoint ↗ 03, 04
1the deliverable is saved, as it always was
2every sprint file naming [#D-9] is re-read, the marker on that line flipped, the file written back through markdown.py
3the open editor reloads, or its draft is flipped in place
New writer, new failure modes. Everything below is about this arrow.
It is rarely one file

templates/sprint.mdnever touched — it plans no fortnight
A carried-over line means one tick rewrites two files. The count belongs in what the app says it did.
The file you are editing right now
Rule drawn here: if the Sprint tab has that file open with an unsaved draft, the flip is applied to the draft in the browser and rides out on the next autosave. The server never writes a file the editor is holding.
The alternative — server writes, editor reloads — throws away whatever you had half-typed. There is no third answer that keeps both.
And it says so
Token refresh endpoint ticked — 03.md and 04.md updated. Undo
A file changing without you typing in it is the thing to be loud about. Undo puts the marker back in both files and unticks the deliverable — one gesture, one reversal.
