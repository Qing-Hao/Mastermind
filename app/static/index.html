      Phases, checkpoints & deliverables

      Phases are the work; a ◆ row is a checkpoint the plan is aiming at, between the phases rather than inside one. Drag a ⠿ grip to put either where it belongs in the sequence.       Dependencies

      Links run project to project — which whole piece of work has to land before another can start. Order inside a project is yours to arrange; nothing checks it.

        All projects

        One column per week, labelled with the Monday it starts. The window shows up to six months at a time — pick a length, or Custom… for your own range. Each project starts folded to a single bar over its own dates, filled to how far through it is — each phase an equal share, filled by the deliverables named under it; open one with the ▸ beside its name to see every phase and checkpoint. Drag a phase bar sideways to move that phase; it snaps to a week column, hold Alt to nudge it by single days. The date you are about to drop on follows the cursor, with the weekday added while Alt is held. Nothing else reschedules itself — a project waiting on this one only starts warning. Click a week number on the ruler to read that fortnight day by day; the drawer that opens is read-only.

        Not placed yet

        Projects you have estimated but not dated. Drag one onto the chart to start it that week — its undated phases are laid out back to back from there, in the order you arranged them. Phases that already have dates keep them. A drop can be undone until you reload the page.

        Cross-project dependencies

        Finish to start, in the order they were linked. A link marked V2 is one where the later project already begins before the earlier one finishes.

          Team map

          Your department at the centre, tracks around it, projects on the outside. Write a track as Source expansion / Metrics to split it into a subtrack. Circle size is total effort points; the percentage inside — and how far the circle is filled — counts each phase as an equal share filled by the deliverables under it, and a numbered pip is the project's tier. Each label shows phases done and what lands next. Dashed circles are future directions — ideas nobody has committed to yet, switched off here by default and listed in full below. Point at a project to dim the map down to it and whatever it is linked to, with arrows running predecessor → successor. Click a project to open it.

          The same projects, placed on the quarter their dates land in. Rows are tracks and a project's subtrack rides on its chip; a project that runs past a quarter is drawn again in the next one as a tail. Write what a quarter is for in its header — that goal and its target are the only stored things here, and nothing under them is rewritten by either. The last column is committed work carrying no dates: give one a date and it moves into a quarter. Nothing on this grid reschedules anything.

          Edit tracks — add or remove a level

          A track is not a record of its own — it exists because projects name it. So + level inserts a new parent above the level you pick and brings its whole subtree with it, and remove takes a level out so whatever was under it rises one. Both rewrite the Track field on every project underneath, which is why each one says how many before it happens. Grouping a second branch under the same name is a second insert: two levels spelt alike under different parents stay two rings, because a project carries one path.

          Future directions 0

          Somewhere to park an idea as it occurs to you. Promoting one keeps its id and anything you have already written against it. Links here are the same project-to-project dependencies the Project tab writes, so an idea can be tied to the work around it without opening it.

            Sprint file

            The sprint file itself, edited in place, and saving happens on its own. A marker applies as you type it and stays applied: ## and a space is a heading you then type into, - is a bullet and - [ ] is a checkbox you can tick. Inline markdown draws the same way — **bold**, *italic*, `code`, ~~struck~~ and [label](url) as you close them, or Ctrl+B/I/U over a selection. Click any block to type in it; a list and a quote are edited a line at a time, and a table cell draws its own markers too. / on an empty block inserts one. In the margin, + adds a block below and ⠯ drags to reorder — click it to insert above or below, or delete. In a table the same handle sits beside every row and above every column — drag it to move that one, click it to insert or delete there. Nothing here writes to the roadmap: a sprint that overruns is recorded in Reflection, and phase dates are changed by hand in the Project tab or not at all.
